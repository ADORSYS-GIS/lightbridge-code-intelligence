What is Lightbridge Code Intelligence?

An AI code reviewer — GitHub, GitLab, and Bitbucket

big picture

What it offers

Not a linter — a repo-aware reviewer and a repo you can ask questions

Inline code review
Findings posted as PR comments, grounded in the real repo, not just the diff
Repository Q&A
@mention a question on an issue or PR — a conversational answer, not a forced review
Deterministic + reasoning
SAST (opengrep) finds the certain stuff; the model investigates and explains the rest
Hybrid retrieval
Structural graph + semantic search ground every finding and every answer
big picture

How a review is configured

Repo-configurable presets, not a hardcoded fast/deep split

fast
Default on every PR open — SAST + one quick, diff-only LLM pass
deep
Default on @mention — full graph + vector retrieval, repo-aware
ultra
Opt-in — the platform's strongest model, widest budget
Shipped defaults, not fixed tiers: a repo can pick its own preset per trigger. Every preset uses the same tools and gates — only the model and budget change.

What actually drives the review?

OpenCode — a vendored AI coding-agent runtime, not a native integration

review flow

How it's actually spawned

A child process, driven over the Agent Client Protocol (ACP)

review flow

What it's actually fed

Two channels: a system prompt (once) and a user prompt (per turn)

System prompt
Operator persona (ai-helm config.reviewSystemPrompt) + a code-owned tool protocol, appended last. Written to review-prompt.md, read once as OpenCode's own agent.build.prompt.
+
User prompt
The maintainer's request + the diff (file-boundary-packed, budget-capped) + repo instructions/memory. Sent as the ACP session/prompt text — re-sent each driver cycle.
"Investigate with the search/graph tools before making any claim — never speculate about code you have not looked up. ... Nothing you record is posted until you call `finish` with your overall verdict — call `finish` exactly once when you are done, even if you found nothing."verbatim — TOOL_PROTOCOL, services/review-agent/src/prompt.rs:47-62 (appended after the operator's own prompt)
review flow

The tools it actually has

All mediated — over the lightbridge MCP server, plus one optional second server

vector_semantic_search
pgvector: find code by meaning
graph_find_symbol
Neo4j: look up a symbol
graph_get_callers
Neo4j: reverse call graph
graph_semantic_search
hybrid: symbols by what they do
read_file
read source, 64 KiB slices
add_review_comment
record one inline finding
retract_finding
drop one that didn't verify
add_comment
plain reply, not diff-pinned
run_sast
deterministic opengrep findings
finish
post everything, verdict required
abort
bail cleanly, buffer discarded
report_progress
progress note, observability only
Plus two optional surfaces: operator-configured external knowledge MCP servers (ADR-0066), and a second, separate read-only GitHub MCP server offered only to GitHub-platformed tasks.

Foundation

What is Code Intelligence?

The ability of an automated system to deeply understand source code — its structure, semantics, and relationships — the exact way an experienced engineer does when reviewing a pull request.

📐

Structure

We map the grammar of the code to understand exactly where functions, classes, and modules begin and end, rather than treating code as raw text.

💬

Semantics

We convert code into mathematical vectors, enabling the AI to answer conceptual questions like "Where do we handle authentication errors?"

🕸️

Relationships

We build a searchable web of dependencies. The system knows exactly which functions call the code being modified in the current pull request.

Core Technologies

Five Pillars of the System

01

Syntax Trees

The grammatical blueprint of the code. It strips away formatting and comments to reveal the pure logical structure of the application.

02

Tree-sitter Engine

The ultra-fast parser we use to generate these syntax trees. It is highly tolerant of errors and supports multiple programming languages.

03

Knowledge Graph

A database mapping how everything connects. Every function is a node; every function call is an edge connecting them together.

04

Vector Embeddings

Code translated into high-dimensional space. It groups code by *meaning* rather than by exact keyword matches.

05

Security Pattern Checks (Opengrep SAST)

Rule-based vulnerability scanning that helps catch known security patterns without relying only on AI judgement.

Concept 2 of 5

The Tree-sitter Engine

The industry-standard parsing technology powering our intelligence.

🛡️

Error Tolerant

Unlike traditional compilers that crash when they hit a syntax error, Tree-sitter gracefully skips the broken line and continues parsing the rest of the file perfectly.

⚡

Lightning Fast

It is designed for incremental parsing, meaning it can instantly update its understanding of the code the moment a developer types a new character.

🌐

Multi-Language

A single unified interface allows us to parse Rust, Python, TypeScript, Java, and many others without having to write custom logic for each language.

Concept 5 of 5

Security Pattern Checks (Opengrep SAST)

Pattern-based security scanning that gives the review agent concrete findings to consider.

🎯

Rule-Based Findings

Opengrep matches known-bad code patterns using a curated ruleset. The scan is rule-driven, so the AI can focus on context and judgement.

⚡

Diff-Scoped Speed

Instead of scanning an entire repository, the scanner targets only the files touched in the pull request, returning results in seconds.

🤝

AI Synergy

SAST findings are passed to the AI agent as context so it doesn't re-report known issues and can focus its budget on what Opengrep cannot catch.

The Lifecycle: Step 1

The Trigger

How the system seamlessly integrates into the developer workflow without blocking progress.

Automatic Trigger

Pull Request Opened

The moment a developer opens a pull request, the system detects it and instantly kicks off a high-speed review task. No manual intervention required.

On-Demand Trigger

@mention in a comment

If a maintainer needs a deep architectural dive, or wants to ask a specific question, they simply mention the bot. This triggers a comprehensive, context-aware analysis.

Maintenance Trigger

Push to Default Branch

When code is finally merged into the main branch, the system quietly rebuilds its indices in the background, keeping the repository's brain fresh for the next review.

The Lifecycle: Step 3

The Two-Tier Strategy

Balancing instant feedback with deep architectural insight.

⚡

The Fast Tier

Runs automatically on every new PR. It uses a faster model, disables deep repository retrieval, and focuses strictly on the visible diff and security pattern checks.

  • Speed: Completes in under 2 minutes.
  • Scope: Diff-only + Security rules.
  • Goal: Catch obvious typos and glaring errors instantly.
🔬

The Deep Tier

Runs when explicitly requested. It uses a frontier AI model and grants full access to the structural graph, semantic index, and file reading capabilities.

  • Speed: Asynchronous, up to 2 hours if highly complex.
  • Scope: Full repository awareness.
  • Goal: Architectural integrity and complex bug hunting.

The Lifecycle: Step 5

Final Quality Gates

The final checks before anything is ever shown to a human developer.

📋

The Coverage Gate

We prevent rubber-stamping. If the AI attempts to finish the review without explicitly reading or commenting on every single file changed in the pull request, the system bounces it back and points out exactly what was ignored.

✂️

Diff Alignment

Findings must accurately anchor to lines that actually changed. If the AI comments on a line outside the diff, the system intelligently categorizes it as a "deferred" finding, rather than dropping it or breaking the GitHub integration.
